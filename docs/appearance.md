# Appearance and dialog cancellation

September 14, 2026. Settings → Appearance offers OLED black (default) and light blue. Each theme has 30 independent color roles covering surfaces, text, controls, status, charts and muscle coverage. Colors accept a picker or six-digit hex input. Group buttons keep the editor compact. Switching themes retains each custom palette; Reset clears only the selected theme's overrides.

Preview is local until Save Settings. Cancel changes returns to the saved profile. The optional `appearance` profile JSON field uses existing account/version conflict checks and portable exports; no migration or change to analysis consent. A validated browser cache applies saved colors before paint, then the loaded account profile takes precedence. Cache failure falls back to OLED. The editor uses the chosen base palette so low-contrast custom values do not hide its recovery controls.

Default text and control contrast is tested against [WCAG 2.2](https://www.w3.org/TR/WCAG22/): 4.5:1 for ordinary text and 3:1 for input outlines/focus indicators. The white/blue palette is a design choice. [Palmer & Schloss (2010)](https://pmc.ncbi.nlm.nih.gov/articles/2889342/) explains color preference through associations and experience; it does not establish a universally best app color. Semantic status colors also have text labels. Muscle colors express estimated set ranges, with numbers available independently.

The latest September 15 request supersedes the earlier contrast-check UI. The preview is now an element selector: buttons, text, surfaces, scores, allowance bars, trends and muscle regions open a focused color dialog. Related element parts (such as button fill/text or input fill/outline/focus) are available in the dialog. Apply changes only those colors; X, Escape and Cancel discard the picker draft. The muscle map selects the clicked region's estimated-set color range and changes no workout data. The preview precedes manual color groups on narrow screens. Editor and dialog controls keep the readable base palette even when custom colors have poor contrast.

Three optional named `appearance.savedThemes` slots store complete palette snapshots and their dark/light mode. Each slot can be applied, replaced/renamed from current colors, or removed. Applying a snapshot copies its palette, so later edits cannot mutate saved slots or the other mode. Slot changes share the existing Save Settings / Cancel changes contract and versioned account save/export. Legacy profiles remain valid. Strict validation allows only slots 1–3, unique slots, bounded names and complete known six-digit hex colors. No migration. Older code with the strict pre-slot schema cannot safely read new profiles; prefer a compatible forward fix after use.

Preview recommended colors is an optional, local action. It adjusts failing text/status/control colors toward a readable tint; only incompatible mixed surfaces are harmonized. It does not change chart or muscle range colors, transmit data, or claim accessibility certification. Nothing changes automatically while picking or saving. Undo restores the suggestion's original overrides while retaining later manual changes and saved slots. Keep colors retains the suggestion in the Settings draft. The former user-facing checklist and warnings are removed; automated checks remain in tests.

All active page CSS, native fields, portaled menus/dialogs and SVG muscle regions inherit semantic tokens. Legacy unused calm.css is historical. Adding a new visible component must not introduce a fixed light/dark palette. The default root CSS must match the TypeScript OLED preset; bootstrap runs self-contained from compiled HTML and never interpolates arbitrary CSS or cached script.

## Dialog behavior

X, Escape and Cancel use the same discard action for programs, written notes, cardio and routine-builder inputs. Budget recurring-item, category-order and goal dialogs likewise discard unsaved changes when closed. Closing does not delete saved history or cancel a committed request. In-flight and unconfirmed writes remain protected so an exact retry can reconcile their outcome. Dictation callbacks are cleared before aborting, preventing a late transcript from repopulating a discarded draft. Saved workout sessions continue unaffected.
