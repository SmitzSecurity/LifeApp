# Category editor and UI previews — September 15, 2026

Category allowances → Edit opens a single draft for names, monthly amounts, order and category removal. Expand a row to edit its fields or confirm Delete. Save changes commits that editor's changed items together; X, Escape and Cancel discard its unsaved draft. Removing a category hides it from allowances and new transaction choices, while retaining its archived ID, past transactions and recurring references. Removed categories can be restored in the same editor. Recurring items are not silently deleted or paused by deleting a category.

The new `budget-item` / `category-edit` action compares only submitted category changes and an optional ordering change. It uses the existing bounded CAS save, exact retries and account isolation. A conflict applies none of the draft. Omitting ordering allows concurrent category reordering or unrelated additions; an explicit order compares only ID sequences and preserves all category objects. No migration or new stored fields. Existing `category` and `category-order` actions remain compatible.

Normal category expansion is an activity view, with upcoming payments, Enter actual / Confirm and recorded transactions. It uses the same recurrence occurrence ID and versioned transaction save as Expected income & expenses, so both views update the same payment. Estimates remain forecasts until confirmation. Editors have separate dirty scopes; collapsing sections or removing a category/recurrence preserves an existing payment draft until saved or cancelled. Archived categories with unfinished drafts stay visible temporarily.

Appearance's latest update replaces the earlier contrast checklist with an optional recommended-color preview and Undo. Click preview elements to open their color picker; three custom theme slots save with Settings. See docs/appearance.md. The editor uses safe base colors while the preview uses the draft palette. Preview data is synthetic and changes no logs; Save Settings and Cancel retain existing versioned profile behavior. No claim is made that chart or muscle colors alone satisfy accessibility criteria.

Validation includes atomic editor saves and conflicts, exact retries, malformed ID/order rejection, concurrent unrelated changes, accounting/reference preservation and contrast-check identity/dependencies. Browser fixtures cover mobile/desktop, X cancellation, combined rename/allowance/order/delete, Enter actual across both views, preserved drafts through category removal and restored contrast feedback with live map/score colors.
