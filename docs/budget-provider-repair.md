# Budget provider repair and owner allowance — September 16, 2026

Budget AI uses its full JSON schema in the system instruction and validates the resulting draft locally, following the working routine builder. Budget requests omit provider output-schema configuration. Ordinary analysis requests are unchanged. The owner approved one Budget recovery and approximately $1/day during development; existing accounting and private identity controls remain intact.

Initial diagnosis against Google's [live v1beta discovery](https://generativelanguage.googleapis.com/$discovery/rest?version=v1beta) and [REST reference](https://ai.google.dev/api/generate-content#TextResponseFormat) found that responseFormat.text.mimeType requires APPLICATION_JSON, not application/json. A synthetic invalid-key request reproduced that enum error without generating content. Correcting the enum and then trying the documented responseMimeType/responseJsonSchema pair still received HTTP400 on live builds. The provider did not identify a specific field. Tests now verify the final instruction-based Budget request and reject malformed, truncated, negative-amount or unexpected-field drafts without saving budget resources.

Known rejections expose only a fixed diagnostic category: credentials, schema, output-format, thinking, model-configuration or request-configuration. Never echo, persist or log raw provider descriptions, input or credentials.

The established schema fields also received a generic INVALID_ARGUMENT with no details. A temporary owner-only redacted diagnostic confirmed that exact response and has been removed. Budget now uses the same JSON-instruction approach as the working routine builder: its full schema is included in the system instruction instead of provider schema configuration. Strict parsing, reference checks, amount bounds and the separate review/adoption step remain unchanged. Malformed drafts cannot be adopted. Written-workout generation remains disabled at the HTTP boundary.

Live generation then exposed an independent validation mismatch: unused week/weekday fields were null for annual and fixed-date payments. The parser now normalizes only nonapplicable null/omitted schedule controls to existing internal defaults. Monthly weekday schedules still require their week and weekday; fixed-date and annual schedules still require their day, and annual renewals require a month. Invalid dates, amounts and category references remain rejected. The temporary format diagnostic was removed; generated text is never returned on an invalid draft.

An explicit HTTP400 `INVALID_ARGUMENT` response without usage/candidates is a known rejection, recorded as `failed` / `provider_request_rejected` with zero usage and an exact replay that cannot dispatch again. Network/server errors, malformed errors and missing receipts retain unknown holds. Provider errors are not echoed with potentially private text. Historical attempts have no original receipt, so their statuses and null costs remain unchanged: an operator acknowledgment may release only the diagnosed original Budget request and its linked consumed recovery from admission blocking. Their two reservations remain in `life_ai_usage`; no request is resent automatically, no grant is renewed, and unrelated unknown attempts still block. The acknowledgment is not available through public writes and must round-trip through export.

Owner attempt limits remain 25/day, 10 per builder/day and five analysis regenerations/day. Ordinary accounts retain $1/account/month and the original $5/month shared ordinary pool.
