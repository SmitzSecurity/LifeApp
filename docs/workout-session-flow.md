# Workout selection and focused sessions

September 16, 2026. This refinement uses the existing workout resources and migrations through 0010. No schema migration or production setup change is required.

## Select and preview

Workouts opens as a program selector with the selected program's muscle coverage and exercise preview. On desktop, muscle coverage is on the left and the session preview is on the right, with equal-height cards. On stacked mobile layouts, the session preview comes first. Edit session stays at the top right beside the session name, including narrow layouts and enlarged text. Selecting a program updates the preview and program coverage together. Weekly plan and actual weekly coverage remain available, along with written workouts, cardio, history, training analysis and the existing program tools.

Training analysis sits above the selector. Its subtitle includes this week's logged sets and sessions, the date range and last week's set count. Write workout, Log cardio and History are text actions at the bottom right. Budget goals, Build with AI and Annual bills fund are also aligned at the bottom right of Budget.

The main preview is a simple exercise list showing order, working-set counts, rep ranges, starting loads and rest targets, without per-row editing or movement controls. Edit session reuses the existing exercise editor to add or remove exercises and change the workout name, exercise names, sets, rep ranges, loads, units, rest or muscle assignments. Apply to session validates the complete draft and changes the preview only. Reset session restores the selected saved program. The separate program-row edit action still edits the saved template through its versioned save.

Reordering lives inside Edit session and the saved-program editor. Hold and drag an exercise's 44px grip; mouse or pen movement can also begin a drag directly. A drop marker shows the new position, and the list scrolls at its edges for longer plans. The grip is the only visible reorder affordance; instructional text and keyboard reordering were removed at the owner’s request. Escape or pointer cancellation leaves the order unchanged. Dragging commits the new order to the editor draft only on drop; Apply to session or Save program remains the separate action that adopts it. Stable exercise IDs keep the selected exercise and its numeric drafts intact. The former Move earlier button is removed.

Program muscle coverage reflects the selected session preview, including changed sets and muscle assignments. Weekly plan continues to use saved programs and their explicit frequencies; This week continues to use logged working sets. A local session edit must not silently alter either of those totals. Equipment & preferences is removed from the preview and editor UI, while existing `preferences` values remain in saved data and carry through template edits and copies.

Session previews are held in memory per program, so switching programs or visiting another app tab does not discard applied changes. Unapplied edits remain in the session editor until Apply or Cancel; X and Escape discard only that open editor's draft. Changed previews warn before page unload, as unsaved set entries do. They are not silently persisted to the account or restored after a browser reload.

An unchanged preview starts directly. A changed preview first offers Begin without saving template, Overwrite existing template & begin, or Save as new template & begin with a name. Back to preview leaves the applied changes available. These choices appear only when the preview differs from the saved program. Overwrite uses the saved template's version; creating a new template gives it a new ID and independent exercise IDs. Neither action changes an existing workout snapshot.

Starting creates a validated deep copy of the reviewed session plan. A fresh session may have a different name, exercise list, order and targets from its template; it must still reference one of the authenticated account's active saved programs, contain valid unique exercise definitions and begin without logged sets, skipped sets, a rest deadline, completion or deletion. This supersedes the earlier requirement that a start contain exactly the saved program's definitions. Once the start is saved, the session's name, date, program identity and exercise snapshot remain immutable even if the saved template is subsequently edited.

Template save and workout start are separate ordered writes. The start is submitted only after the template save is acknowledged. An unknown template result retains that exact template ID, expected version, exercise IDs and payload behind a reachable Retry template save & begin action. After template acknowledgement, an unknown workout start retains its own exact workout ID and snapshot for Retry workout save; it must not repeat the already-confirmed template save. Both stages preserve navigation locks, and definite template conflicts require a deliberate resolution rather than automatic overwrite.

## Work through a session

An active workout fills the entire available Workouts workspace between the app header and navigation, without a centered card or outer margins. Its top controls stay visible while the exercise content scrolls on short screens, including keyboard-sized viewports. Each new set or rest period begins at the top of that content area. The view focuses on the current exercise or rest period. It shows the exercise's position, working-set target, exact reps and load inputs, warm-up choice and next exercise. The top-right information control opens Workout information with the session name, date, progress, plan, logged sets, corrections and deletion controls. Adjacent sound and vibration controls are explicit, optional toggles. Historical exercise snapshots and set identities are unchanged.

The exercise artwork uses locally bundled, attributed Everkinetic and Workout Guide illustrations. Verified original start/end drawings loop every 1.2 seconds, using shared bounds so equipment and body scale stay aligned. A 44px pause/play control sits on the artwork. Reduced-motion preferences start the illustration paused; explicit Play can enable it. Offscreen or background demonstrations stop ticking. Other matched illustrations remain static, and unsupported exact variants use a neutral dumbbell instead of an incorrect pose. Artwork is allowed independent paper/ink colors; app controls still use semantic theme tokens. Attribution and source licenses are reachable from Workout information.

A small help link beside the centered exercise title opens an exercise-specific guide in another tab without losing the session. Reviewed pages favor MuscleWiki demonstrations and technique notes, with other providers where the match is closer. Unverified exact variants and custom names get a clearly labelled search. No external exercise media is embedded or fetched automatically. See [exercise guide provenance](exercise-guides.md).

Saving a set keeps the existing stable per-exercise serial. Warm-ups remain additional sets and do not consume planned working sets. Only explicitly logged sets contribute to actual activity and coverage; unlogged targets are never inferred as completed work.

Skip set advances the current planned working set and discards its entered draft. It stores optional `workout.skippedSets` entries containing `exerciseId` and `workingSetNumber`, separate from actual set logs. The working-set number is the planned ordinal within an exercise, independent of the stable logged-set serial and any additional warm-ups. Skips survive reload, preserve exact retries and do not create reps, load, volume, habit credit or completed-set counts. Progress and the session plan show logged and skipped sets separately. Existing workouts without this optional field retain their original behavior; no migration is required.

After skipped sets have been saved, use a compatible forward fix. Older binaries that reject or ignore `skippedSets` cannot safely resume or export these sessions.

Below Target, Last time shows the reps and load for the same working-set ordinal from the latest completed workout that logged that exercise, across programs. Matching uses the shared exercise-name resolver, including known aliases while retaining meaningful equipment and grip differences; exercise IDs need not match across programs. Historical units are displayed as logged, without conversion. Warm-ups are excluded. A skipped or missing ordinal in the latest matching workout produces no previous performance for that set; another ordinal or older session is not substituted. Deleted workouts are excluded. Reads are account-scoped and bounded independently of the paged history display; an unavailable lookup does not prevent logging the current set.

Between sets, the view shows the rest countdown and next set. Skip rest clears the saved deadline. +20 seconds extends from the current deadline, or from the current time if rest has expired, subject to the existing fifteen-minute cap. Rest saves preserve any entered set draft and correction state. The absolute deadline survives refresh and elapsed time away from the tab. Sound and vibration begin off, are enabled by an explicit click and depend on browser support. The rest sound uses a local browser-generated tone. The page must remain open for alerts; browser background and device behavior can affect delivery.

## Exit, return and finish

The top-left X opens Leave workout? with Finish with logged sets and Cancel workout. Closing that dialog with its top-right X or Escape returns to the active workout without changing the current entry. There is no separate Keep training button. X no longer sends the user to a selector or a separate Resume tile. To check another app section, use normal app navigation; returning to Workouts restores the active session. The Workouts component stays mounted, including refreshes requested by Trash, so an unsaved rep/load entry remains available when the user returns. Reloading the browser restores the saved active workout and logged sets; an unsaved set entry is browser-memory state and triggers the normal before-unload warning instead of being silently saved.

The completed-plan Finish workout action writes the explicitly logged session directly and releases the active-session slot. The X dialog also permits an early Finish with logged sets, which explicitly discards any unsaved current entry as disclosed in that dialog; only saved sets are included. Remaining targets stay unrecorded. Cancel workout is an explicit choice in the same confirmation dialog and moves the session to the existing seven-day Trash, excludes its logged sets from actual totals and frees the slot. Restore follows the existing version and single-active-session checks. Finished sessions cannot be reopened as active workouts.

In-flight or unconfirmed writes keep the existing navigation lock and exact pending payload. Retry uses the same workout ID, expected version, set identities, skip metadata, timestamps and rest deadline; it does not recalculate a timer or create another workout. Rest-only saves leave the current entry intact. Set saves and skips advance the entry only after acknowledgement. An unconfirmed completed-plan finish retains a visible Retry workout save action in the session; an unconfirmed early finish or cancellation retains its retry inside the X dialog.

The normal Refresh control is removed. Read-only reconciliation runs when returning to Workouts, returning focus to the browser, and periodically while the page is visible. It never replays a write or replaces an entered set, pending save, session preview, session editor or program draft. A response started before a write cannot overwrite the newer state. Weekly summaries update after confirmed saves. Error recovery may still offer a read-only retry; the user does not need to refresh as part of normal workout use.

After a definite write conflict, an entered set can be explicitly discarded with Discard set draft and reload. This recovery keeps pending-write locks, disables entry during the read, and clears the draft only after the saved workout is successfully loaded.

## Session presentation

The current exercise heading, symbol, working-set target and entry form share one centerline, including when a content scrollbar appears. The target block occupies the flexible center area; Ready when you are sits directly above reps and load. Shorter screens use smaller artwork and tighter spacing, with content scrolling when enlarged text needs it. Rest centers the complete label/countdown/action group in the workout display, with equal space above and below. The next-exercise header is centered between the top of that display and the rest group. Very short screens use normal vertical flow and scrolling so header and controls cannot overlap.

Local SVG pictograms cover all 79 preset exercises and their 87 catalog aliases across 37 pose families, with equipment/grip variants. They inherit semantic primary/background colors, have no external asset requests and remain decorative rather than technique instructions. Unknown custom names use a neutral dumbbell symbol. Exact catalog matching avoids guessing a specific pose for an unfamiliar custom exercise; workout data and exercise matching for previous performance are unchanged.
