## Follow-up: debt-format conflicts

A later owner request failed at `recurring.1.debt (custom)`. The failed raw output is not retained, so that path alone cannot distinguish a balance-only schedule conflict from card accounting or missing status. Loan generation now receives a loan-specific JSON shape: required non-null debt/status, monthly schedules, no category suggestions and explicit unknown interest accrual. Budget's general shape is unchanged, and neither mode adds provider schema configuration.

Only loan-mode parsing normalizes valid unused payment fields for balance-only loans, retaining meaningful amounts/dates/installments in named review notes. Missing payment status becomes balance-only, never an assumed bill; missing interest status becomes unknown with statement tracking, never assumed accruing or paused. Credit-card accounting uses transfers and statement balances while preserving the reported balance and rate. Positive separate card interest/deductions remain rejected with precise field paths because their relation to the stated balance is ambiguous. Malformed amounts/dates, unsupported debt schedules and nonloan items still fail. No live loan records, holds, allowance, expiry or migration change.
