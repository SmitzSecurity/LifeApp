# Income rules — September 16, 2026

Recurring income optionally stores `incomePlan`: up to eight named withholdings and savings/investment targets. Withholdings are user-entered fixed amounts or percentages of gross; transfer percentages use take-home pay. Each rule rounds to cents. Withholdings must leave positive take-home pay and combined targets cannot exceed it. There is no tax-rate estimation or bank action. Without rules, income behaves as before.

The recurring amount becomes gross pay when rules are enabled. Confirm payment previews the breakdown, saves take-home as the income transaction's actual amount, and stores `incomeDetails` with gross and the policy snapshot. Changing the recurring item later affects new confirmations only. Correcting a saved income amount recalculates from that transaction's original policy; it never rewrites any previously saved transfer. Existing income transactions without a policy remain unchanged.

Savings/investment prompts are derived from the confirmed income snapshot and have stable `allocation:YYYY-MM:recurring-id:saving|investing` IDs. They do not count as actuals until separately confirmed. Both prompts support editing and Delete; deleting an unrecorded prompt creates a planned tombstone in central Trash. Once a transfer record exists, it suppresses derivation regardless of actual, voided or deleted status. Transaction reads also return this month's `suppressedAllocations` from permanent Trash tombstones, preventing a deleted prompt from reappearing after seven days. Cancel/X use the existing exact-retry locks, and open prompt drafts remain mounted if the source income changes elsewhere.

Allocation creation validates the source income and guards its version in the same insert; corrections retain the original source and month. A confirmed transfer remains a real ledger record if its source income is later voided/deleted. This preserves financial history and avoids reversing a bank transfer that the app never performed. Backup validation accepts these linked IDs even after the source's permanent deletion. Existing purge triggers scrub the optional fields without migration changes.

No migration is required. After these optional JSON fields or allocation IDs are saved, use a compatible forward fix rather than rollback to code that rejects them. Budget AI import does not create income rules in this release; users review and set them on recurring income.

Synthetic tests cover fixed/percentage deduction math and rounding, net totals, forecast exclusions, invalid policies, stable IDs, immutable historical rules, separately confirmed amounts, exact retries, account/source validation, Delete/Trash suppression and lossless export after deleting the source income. Browser checks should cover enabling rules, empty numeric fields, gross previews, separate confirmation and deleting a prompt at mobile and desktop sizes.
