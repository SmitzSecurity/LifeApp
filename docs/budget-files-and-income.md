# Budget files, recovery and income planning — September 16, 2026

The Budget Month metric is one clickable tile with MM/YYYY display and the existing native/fallback picker. Dirty-month navigation remains guarded. Other metric sizes, semantic colors and 64px navigation remain unchanged.

Budget AI accepts TXT, Markdown, CSV, TSV, JSON, XLSX, DOCX, PDF, JPEG, PNG and WebP. Old DOC/XLS formats need export to a supported format. Text and Office files are extracted locally; image/PDF bytes are sent only on explicit Build. Office extraction uses cached cell values and document text, never executes formulas/macros or fetches external links, and explains omitted embedded images/charts. Missing formula results, encryption, malformed ZIP/XML, unsupported encodings and expansion limits fail explicitly. Text remains separate from the short notes input and is combined once into the exact retry payload. The private owner example was read locally in full (321,237 bytes / 320,996 characters); it is not a repository fixture.

Limits: extracted text 500,000 characters and 1 MB, source text/Office files 8 MB, PDF 4 MB, bounded ZIP expansion 24 MB. Image re-encoding retains existing image limits. The dedicated budget endpoint streams at most 7 MB; other endpoints remain 64 KB. The server validates PDF/base64 signatures and fingerprints attachments rather than persisting binary files. Large text/PDF builds call Gemini countTokens before generateContent and reject over 180,000 input tokens, retaining the existing $0.20 reservation, output limit and all shared caps. A typed, pre-generation failure records zero cost and cannot become a permanent unknown-outcome hold. Any dispatched generation/storage uncertainty retains its reservation. Export validation accepts larger budget snapshots only; other namespaces retain their prior bounds.

The current extraction draft supports 20 categories and 30 monthly/annual recurring items. Unsupported frequencies, allocations/withholdings needing separate setup, historical transactions and ambiguous/current-versus-old document revisions are identified in notes instead of silently inventing saved records. All generated items still require review and atomic adoption.

An old uncertain Budget build cannot be silently cleared or resent. An operator may issue an account-scoped, expiring `ai-recovery` resource with `purpose: "budget"` and the original source UUID, only after authorization. One new build records `recoveryOf` atomically; it gets no daily/cost cap bonus and the original reservation remains. After a known complete/failed recovery outcome, its original blocker can be ignored using durable linked-grant evidence. An uncertain recovery or any unrelated pending job still blocks, and recovery chains are prohibited. Grants cannot be issued through public resource writes or consumed by workout recovery. No grant or paid generation is authorized merely by deploying this code.

Income planning is documented in `income-planning.md`. Optional JSON fields require no migration. Preserve 0000–0010, live budgets, existing consent/runtime flags and all unknown accounting. After these fields are saved, do not roll back to code that rejects income metadata, allocation IDs, larger budget snapshots or budget recovery grants.

Provider references: [token counting](https://ai.google.dev/api/tokens), [document processing](https://ai.google.dev/gemini-api/docs/document-processing). These features do not provide bank connectivity or calculate tax liability.
